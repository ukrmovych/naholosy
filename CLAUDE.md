# Мовні ігри («Наголоси») — пам'ятка для Claude

Власник — учитель української, не програміст. Усе робить Claude: пояснюй простою мовою, без жаргону, відповідай українською.

## Що це
Набір мовних ігор для підготовки до НМТ: Наголоси (основна), Лексична помилка, Кличний відмінок, Фразеологізми (бета) + онлайн-режими (дуель, спринт 60 с, гра для класу).
Сайт: https://ukrmovych.duckdns.org/gym/ (раніше був ukrmovych.github.io/naholosy/ — `migrate.js` переносить дані гравців зі старої адреси).
Також відкривається як Telegram-мініапка через @ukrmovych_bot.

## Структура (чистий HTML/CSS/JS, без збирання й без npm)
- `index.html` — головна сторінка, меню режимів.
- `script.js` (~110 КБ) — логіка всіх ігор; список ігор — масив `GAMES` (статуси live/beta/soon); слова для наголосів — `naholosyData` на початку файлу.
- `online.js` (~70 КБ) — онлайн-режими через Supabase Realtime; теми — `ONLINE_GAMES`, режими — `ONLINE_MODES`.
- `klychnyi-data.js`, `frazeo-data.js` — дані ігор; формат описано в коментарі на початку кожного файлу.
- `chyslivnyky-data.js` — «Числівники» (бета, PRO): речення з пропуском, правильна форма, неправильні варіанти, паралельна правильна форма (`also`) і правило; гра як «Фразеологізми» (марафон, 3 життя, «Далі →»).
- `slovospoluch.js` + `slovospoluch-data.js` — «Лексична помилка (словосполучення)» (бета, PRO): словосполучення + «Правильно»/«Неправильно» (клавіші 1/2). Дані — групи `{ id, name, rows: [[неправильно, правильно, пояснення]] }`, з рядка дві картки. Звичайний екран режимів (`showModes`): угорі галочки груп для всіх режимів (`renderSlovoGroupPicker`, localStorage `slovospoluch_groups`, останню зняти не можна); марафон 3 життя (рекорд `best_slovospoluch`), «♾ Без обмеження життів», дуель на одному екрані, онлайн-дуель/спринт 60 с/гра для класу (`ONLINE_GAMES.slovospoluch`; картки — `SLOVO_CARDS`, `online.topic` — id груп через кому, "" — усі). Кнопки «Правильно/Неправильно» завжди в одному порядку (картки з `pair` в online.js не перемішуються). У беті консоль попереджає, якщо правильне словосполучення збігається з неправильним.
  **Спірні випадки — свідомо НЕ додані (власник погодив), не додавати:** «вік знаходиться/перебуває»; «залишати в спокої», «під відкритим небом», «прийшло в голову» (є в СУМ); «музичний/музикальний слух»; «туристичний/туристський»; «поверхневі знання»; «обумовлений/зумовлений»; «напрям/напрямок руху»; «виборна комісія», «дослідний метод», «сусідські будинки», «особиста справа», «пам'ятник архітектури» (обидва варіанти можливі). Також: «відкрити очі» отримало контекст «вранці»; «перебувати в певній відповідності» → «перебувати у відповідності з вимогами».
- `nmt-test.js` + `nmt-test-data.js` — «Рандомний тест НМТ» (PRO): ~430 завдань з однією відповіддю з zno.osvita.ua (розділи /ukrmova/ і /ukrainian/). Правила відбору (власник): НМТ 2022–2026 — усі; ЗНО — морфологія (усі роки), орфографія (лише ≥2021, бо правопис 2019), інші теми — лише типи, що є на НМТ; без завдань із пропусками й літератури. Джерело — підпис без посилання («НМТ-2024», «НМТ-2023 (демоваріант)», «ЗНО-2019 (таке може трапитись і на НМТ)»). У наголосі/звуках виділені букви — `<u>`. Дані вантажаться лише при відкритті тренажера. «Завершити» — підсумок, помилки, рекорд `best_nmttest`. Показані завдання — `nmt_seen`.
- `myclass.js` + `classrooms.sql` — «👥 Мій клас» (для всіх, не лише бета): будь-хто створює клас (назва) → 6-значний код; приєднання — посилання `?class=КОД` / Telegram `startapp=c_КОД`, QR або код вручну. Після кожної гри (`gameOver` → `classOnGameOver`; тест НМТ → `submitClassScore`) найкращий результат іде в таблицю всіх класів гравця, окремо по іграх (без спецтем і «без обмеження життів»). Ідентифікатор — `getPlayerId()`; кеш класів — localStorage `player_classes`. Вихід/виключення — `active = false` (не delete). Адмін-перегляд — статистика, вкладка «Класи» (`get_classrooms_admin`).
- `style.css` — стилі.
- `leaderboard-config.js` — адреса й публічний ключ Supabase, посилання на мініапку.
- `stats/` — сторінка статистики (під паролем); `chill/` — режим «антистрес»; `beta/` — переадресація на `?beta` (вмикає бета-ігри).
- `*.sql` — скрипти для Supabase (копія того, що запущено в базі). Речення «Лексичної помилки» лежать у закритій таблиці `sentences`, їх у репозиторії немає.
- `LEADERBOARD.md`, `ONLINE.md`, `STATS.md` — інструкції для власника.
- `NEW_GAME_PROMPT.md` — готовий промпт для нового чату, щоб зробити нову тему (гру). Власник працює над різними частинами в кількох чатах паралельно: перед змінами `git pull`, нове — в окремих файлах, спільні файли міняти точково, при розбіжностях поєднувати зміни, версію `?v=` ставити новішою за наявну.

## Викладання
Push у `main` → GitHub Actions (`.github/workflows/deploy.yml`) копіює файли на сервер Oracle Cloud у `/var/www/gym` (файли `.sql` і `.md` не копіюються). Сервер спільний із платформою пробного НМТ (репозиторій ukrmovych/testtest — там конфіг Caddy).
- Зміни одразу пуш у `main`; після кожного оновлення давай посилання на бету: https://ukrmovych.duckdns.org/gym/?b
- Секрети `SERVER_HOST` і `SERVER_SSH_KEY` не змінювати, не видаляти, не виводити. `deploy.yml` не має писати за межі `/var/www/gym` чи потребувати sudo. Усі шляхи в грі — відносні.

## Supabase
Підключений до Claude як конектор (проєкт «NMT-Gym», id `eecnmjuxbpejqyafvtfj`). SQL Claude запускає сам через `execute_sql`; `apply_migration` зависав, тому великі скрипти — частинами. Пароль статистики ніде не виводити.
Edge Function `pro-check` (копія — `supabase/functions/pro-check/index.ts`, викладати через `deploy_edge_function`, verify_jwt=false) перевіряє PRO-підписку. Її секрети `TELEGRAM_BOT_TOKEN` (@ukrmovych_bot), `UKR_MOVYCH_BOT_TOKEN` (@ukr_movych_bot) власник вводить сам у Supabase — ніде не виводити. Id каналу «НМТ-качки» записано в коді функції (`PRO_CHAT_ID`, не секрет). Перевірити налаштування: `select net.http_post(...pro-check, body {"setup":true})` через pg_net, відповідь — у `net._http_response`.

## PRO-підписка (Base by mono)
Base додає підписників у закритий Telegram-канал; один із ботів (@ukrmovych_bot або @ukr_movych_bot) — адмін там; `pro-check` перевіряє членство за Telegram initData. Безкоштовно — усе, що в основній версії; PRO — ігри з `pro: true` у `GAMES` (кличний, фразеологізми, числівники, іншомовні…). Поки замочки діють лише в беті (`PRO_ENABLED = BETA`); `?b&pro` — відкрити PRO для перевірки. Посилання на Base — `proLink` у `leaderboard-config.js`. Стан у localStorage — `pro_status`. Для гравців це «Спільнота Укрмовича» (рівень «НМТ-качок» у Base); у текстах не писати «оплата», «купити» — це добровільна підтримка-підписка.
Кнопка «Підписка є, а доступу немає?» з'являється лише після невдалої перевірки «Я вже в Спільноті» → `pro-check` з `report`: запис у `pro_issues` (pro-issues.sql) і повідомлення власнику від бота; учню — «зв'яжуться протягом 24 годин» (заявок у канал не давати). Звернення видно на сторінці статистики, вкладка «PRO».

## Спецтеми за посиланням (вебінари)
- `topics.js` — реєстр тем (`SPECIAL_TOPICS`: назва, значок, правило відбору слів із `naholosyData`). Нова тема — новий запис там. **Усі такі унікальні режими позначати зірочкою ⭐** (бажання власника). У «Тренуванні» спецтеми — внизу, звичайною плиткою, не крупно.
- Гра для класу: кількість слів — 10/20/30 або своє число (кнопки − +, введення з клавіатури), не більше, ніж слів у темі.
- Доступ: посилання `t.me/ukrmovych_bot/battle?startapp=w_КОД` (на сайті `?w=КОД` лише радить відкрити в Telegram). Функція Supabase `topic-access` (копія в `supabase/functions/topic-access/`) перевіряє initData і, якщо до дедлайну посилання, записує доступ назавжди. Таблиці й RPC — `topic-access.sql` (`access_links`, `access_grants`). Керування — сторінка статистики, вкладка «🔑 Доступи» (створити, продовжити/закрити, скасувати всім, забрати в одного).
- Власник: браузер зі збереженим паролем статистики (`stats_password`) бачить усі теми. Кеш доступу — localStorage `topic_access`.
- У грі: група в «Тренуванні» (від'ємний номер групи, `groupAt`), вибір слів у «Наголосах» для марафону й онлайн-ігор (`currentTopic`; онлайн — `online.topic`, `poolIndices()`). Марафон спецтеми — без турнірної таблиці, рекорд `best_topic_<id>`.

## Інше
- «‹ Попереднє» в тренажерах: після відповіді копія картки зберігається (`prevCard` у `nextQuestion`), кнопка показує її у вікні для перегляду.
- PRO: у «Наголосах» кнопка «♾ Без обмеження життів» (`endless`): життя не відбираються, «Завершити» → підсумок; рекорд і турнірна таблиця не зараховуються.
- Статистика: з бети гра нічого не надсилає (`track` → `if (BETA) return`); `get_stats_range` (stats-v3.sql) не рахує події з `details.beta`. Переходи за посиланнями @ukr_movych — подія `brand_click` (place = клас посилання).

## Правила роботи
- Після зміни JS/CSS **оновлюй версію `?v=...`** у тегах `<script>`/`<link>` в `index.html` (формат `?v=РРРРММДДa`), інакше в учнів залишиться старий файл у кеші.
- Великі файли (`script.js`, `online.js`, дані) не читай цілком — шукай потрібне місце пошуком і правь лише його.
- Нове SQL — окремим файлом з коментарем угорі (що робить); повторний запуск не має нічого ламати. Запускай його сам через конектор.
- Ключі доступу (service role, паролі) у репозиторій не додавати — він публічний. Публічний anon-ключ у `leaderboard-config.js` — це нормально.
- Дані гравців (рекорди, прогрес) зберігаються в localStorage з префіксами `best_`, `train_`, `player_`, `duel_`, `stats_` — не перейменовуй ключі, бо гравці втратять прогрес.


## Тимчасове (прибрати, коли скаже власник)
- **PRO-замочки вимкнено** (`PRO_LOCKS = false` у `script.js`): у беті всі ігри відкриті з будь-якого пристрою, «♾ Без обмеження життів» — для всіх у беті. Перед запуском PRO в основному боті: `PRO_LOCKS = true` і перевести PRO-ігри з бети в основну версію (`PRO_ENABLED` зараз залежить від `BETA`). Нагадати власнику під час запуску.
- У беті фінал «ТИ МОЛОДЕЦЬ» кличного відмінка показується вже після 1-го рівня (`script.js`: `newLevel && level === 2 && BETA`).
